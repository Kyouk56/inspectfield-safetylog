# SafetyLog Authorization Worker

A Cloudflare Worker that is the **source of truth** for SafetyLog identity, roles and
entitlements. The Android app no longer decides its own privileges locally: after a real
Google sign-in it exchanges the Google ID token for a short-lived, RS256-signed
**authorization snapshot** and uses that snapshot for all permission checks.

This directly closes the findings D-01, D-02, D-05 and D-12 in
`docs/REVIEW_FIX_VALIDATION_LOG.md`.

## What it does

1. Verifies the Google ID token **server-side** against Google's JWKS: signature, issuer,
   audience, expiry, `email_verified`, and the nonce generated by the app.
2. Reads the user's role, tier, payment status, seats and team roster from a KV registry.
   Nothing the app sends can influence these values.
3. Issues a signed snapshot (JWT, RS256, short TTL — default 15 minutes).
4. Exposes admin endpoints for an OWNER to assign roles / entitlements / roster.
5. Verifies Play Store purchase tokens through the Google Play Developer API before
   granting a paid tier.

## Deploy

```bash
cd server
npm install
cp wrangler.example.toml wrangler.toml
# 1. Create a KV namespace: npx wrangler kv namespace create AUTH_REGISTRY
# 2. Paste its id into wrangler.toml
# 3. Generate the signing keypair and configure secrets:
npm run keys
npx wrangler secret put SIGNING_KEY_PKCS8_BASE64
npx wrangler secret put SIGNING_KEY_SPKI_BASE64
npx wrangler secret put GOOGLE_SERVICE_ACCOUNT_JSON   # service account with androidpublisher scope
# 4. Add AUTH_API_BASE_URL and AUTH_PUBLIC_KEY_SPKI_BASE64 to the app's build config
npm run deploy
```

The app reads `AUTH_API_BASE_URL` (e.g. `https://safetylog-auth.<subdomain>.workers.dev`)
and `AUTH_PUBLIC_KEY_SPKI_BASE64` from `gradle.properties` / environment. See
`docs/SERVER_AUTHORIZATION.md` for the full client-side integration and rollout plan.

## API

| Method | Path | Auth | Purpose |
|---|---|---|---|
| `GET` | `/health` | none | Liveness |
| `POST` | `/v1/auth/exchange` | Google ID token in body `{idToken, nonce?}` | Verify identity, return signed snapshot |
| `POST` | `/v1/auth/email` | `{email, password}` | Verify PBKDF2 inspector credential, return signed snapshot |
| `POST` | `/v1/auth/refresh` | snapshot bearer | Re-check registry, return fresh snapshot |
| `GET` | `/v1/me` | snapshot bearer | Return decoded authoritative claims |
| `POST` | `/v1/admin/credential` | OWNER snapshot | `{email, password, role}` — create/update an inspector login (min 8 chars, never OWNER) |
| `DELETE` | `/v1/admin/credential` | OWNER snapshot | `{email}` — revoke an inspector login |
| `POST` | `/v1/admin/role` | OWNER snapshot | `{email, role}` — OWNER cannot be assigned here |
| `POST` | `/v1/admin/entitlement` | OWNER / ACCOUNT_ADMIN snapshot | `{email, tier, paymentStatus?, seats?}` |
| `PUT` | `/v1/admin/team` | OWNER / ACCOUNT_ADMIN / MANAGER snapshot | `{members: [...]}` |
| `POST` | `/v1/purchases/verify` | snapshot bearer | `{purchaseToken, productId}` → verify with Play, update entitlement |

All authenticated responses are `Cache-Control: no-store`.

## Security notes

- The private signing key exists only as a Worker secret. The app embeds only the public
  key, so it can verify snapshots but cannot forge them.
- A snapshot expires in 15 minutes. Privileged mutations in the app require a **fresh**
  server check (fail-closed offline); read-only UI may use the cached signed snapshot.
- The OWNER allowlist lives in the `OWNER_EMAILS` Worker variable, not in the app.
- `GOOGLE_SERVICE_ACCOUNT_JSON` is optional: without it, purchase verification fails
  closed and no paid entitlement can be granted by the app.
